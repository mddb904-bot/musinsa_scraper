# CLAUDE.md

このリポジトリで作業するときに読むファイル。

## このプロジェクトは何か

AI関連ニュースを平日朝に自動収集し、裏付けを取ったうえで日本語ダイジェストHTMLを作る。
収集した記事はすべてGoogleスプレッドシートに蓄積し、後から検索・分析できるようにする。

読み手はアパレルEC事業者のMD（マーチャンダイザー）。ZOZO出店ブランドの運営を担当し、
BigQueryでの分析やPythonでの業務自動化を自分で行う非エンジニア。
「AIっぽい要約」ではなく、明日の判断に使える形を求めている。

```
収集 → 要約・分類（Claude API）→ 裏付け検証 → HTML生成 → 掲載フラグ更新
                                    ↓
                      すべての行はスプレッドシートに残る
```

## 作業の進め方

**推論で進めず、確認してから動く。**

- 解釈が割れる依頼、前提に依存する作業、後戻りコストが大きい変更は、着手前に確認する
- ただし自明なことまで聞かない。1回のよい確認が、5回のささいな質問に勝る
- 質問は散らさず1メッセージにまとめる。自分の想定プランを先に示してから聞く
- 置いた前提は必ず明示する
- 頼まれた範囲を超えない。よかれと思った追加実装はせず、提案に留める

**「動くはず」で渡さない。** コードを変えたら必ず構文チェックと、可能なら実行して確かめる。
検証しきれない部分が残るなら、どこが未検証かを正直に書く。

**データは参照が既定、変更はオプトイン。**

- スプレッドシート、BigQuery、ローカルファイルは、読む・調べるは自由
- 削除・上書き・権限変更は、明示の指示があるときだけ、かつ実行前に確認する
- 迷ったら非破壊で。既存を書き換える代わりに、新規タブ・末尾追記を優先する

## 触ってはいけないもの

- **`articles` タブの既存行。** 追記と、指定した列の更新だけ。行の削除はしない
- **`ARTICLE_COLUMNS` の途中への列挿入。** 既存行との対応がずれる。足すなら必ず末尾
- **`sources` タブ。** 情報源の追加・停止は人が手で編集する。スクリプトからは読むだけ
- **検証に落ちた記事の削除。** 消すと「検証していない」事実まで消え、後から
  「そのニュースがなかった」のか「拾えなかった」のか判別できなくなる

## コード規約

Python:

- コメントと docstring は日本語。識別子は英語
- 文字列フォーマットは `%` 演算子を使っている。統一のため踏襲する
- 外部からの取得（HTTP、API）は失敗しても全体を止めない。空を返して次へ進む
- ログは `print` で日本語。何件処理したかを必ず出す

BigQuery（将来この仕組みをBQに載せる場合）:

- 日本語列名はバッククォートで囲む
- カンマは文頭に置きスペースなし（`,column_name`）
- `AS` 句はインデント開始位置を揃える
- `SAFE_DIVIDE` は使わず `IF(分母=0, 0, 分子/分母)` で統一
- `SAFE_` 関数、`BETWEEN`、`FULL OUTER JOIN` は使わない
- 日本語の `AS` 句内に `()` を使うとエラーになるので使わない
- プロジェクトは `ada-bigquery`

## 検証ロジックの設計意図

ここを変えるときは背景を踏まえること。

**目的は「正しい情報だけを集める」ではなく「どこまで裏付けが取れたかを記録する」。**
発表内容そのものの正しさは検証できない。全社が同じプレスリリースを引き写していれば、
何社が報じていても裏付けにはならない。`verified_primary` は「一次発表と一致している」
であって「事実である」ではない。

実際に効くのは次の2つ。

1. **数値の突合** … 要約に出てくる数値が取得元の本文にあるか照合する。
   AIの要約で最も壊れやすいのが数字であり、社内で引用したときの実害が最も大きい
2. **一次発表への到達** … まとめ記事経由だと日付がずれる。実際に、まとめ記事から
   拾った発表日が2週間ずれていた例と、存在しない割引条件が要約に混ざった例がある

**食い違いは多数決で切り分ける。** 1社の誤報でグループ全体を落とさないため、
多数派と一致する記事は通し、少数派だけを `conflict` にする。
1対1で割れた場合は多数派が決まらないので両方保留。

**タイトルの類似判定は文字バイグラムのDice係数。** `difflib.SequenceMatcher` は
日本語の見出しで分離が出ない（同一事象で0.55、閾値割れ）。Diceだと同一事象0.5前後・
無関係0.0付近と明確に分かれる。閾値は 0.35。ここを `difflib` に戻さないこと。

## よくある作業

```bash
# 通常実行
python -m src.run_daily

# シートに書かずHTMLだけ確認
python -m src.run_daily --dry-run

# 要約プロンプトを直したあと過去分を作り直す
#   1. articles の title_ja 列を空にする
#   2. 下を実行（生の収集列は残っているので何度でもやり直せる）
python -m src.run_daily --skip-collect

# フィードの疎通確認
python -m src.setup_sheet --check

# 構文チェック
python -m py_compile src/*.py
```

要約プロンプトを変えたら `config.PROMPT_VERSION` を上げる。
上げないと、過去の要約と混ざって傾向分析ができなくなる。

## 既知の制約

- 記事本文は冒頭800字しか保存しない。本文後半にしかない数値は
  `summary_mismatch` として弾かれることがある。誤検出側に倒してある
- 数値照合は文字列一致。「5,000」と「5000」は吸収するが
  「50億」と「5,000,000,000」は別物と判定する
- `collect.py` の一次発表URL解決は実サイトのHTML構造に依存する。
  取れなくても空文字を返して落とさない作りにしてあるが、精度は情報源次第
